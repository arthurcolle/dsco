What changed

Cloud endpoints are treated as first-class OpenAI-compatible providers. The model identifier chooses the model, while environment variables choose the endpoint and authentication surface.

Provider
modal

Custom Modal endpoint routing through `MODAL_ENDPOINT_URL`.

Auth
proxy

`Modal-Key` and `Modal-Secret` headers from local runtime env.

Protocol
OpenAI

`/v1/chat/completions` with streaming, tools, and normal dsco turn accounting.

Request path

The routing surface stays small: one endpoint URL, one provider pin, and a normal model name. The agent loop does not need Modal-specific business logic.

PromptUser submits a coding task through the dsco TUI or one-shot CLI.
Route`--provider modal` selects the custom endpoint transport.
HeadersProxy credentials become Modal headers, never prompt text.
SGLangModal serves GLM-5.2 FP8 on 8x B200 using the OpenAI schema.
Agentdsco streams text, parses tool calls, and continues the coding loop.

Architecture

Native Z.AI remains the default low-friction path. Modal becomes the heavy cloud lane for latency, throughput, and custom serving experiments.

Use `glm52` for native Z.AI coding-plan API. Use `modal/zai-org/GLM-5.2-FP8` only when you intentionally want the 8x B200 cloud deployment.

End-to-end smoke

The script reads Modal proxy credentials from `/tmp/modal_proxy_token.json`, probes readiness, sends a direct OpenAI-compatible request, and then sends the same prompt through dsco.

export ZAI_API_KEY='...'
dsco -m glm52 'Reply with exactly OK.'

DSCO_SECURE_STORE_NO_PROMPT=1 dsco --route-explain glm52
export MODAL_ENDPOINT_URL='https://arthurcolle--ep-agent-server.us-west.modal.direct'
export MODAL_KEY='...'
export MODAL_SECRET='...'

dsco --provider modal -m modal/zai-org/GLM-5.2-FP8 \
  'Reply with exactly OK.'
scripts/test_modal_dsco_live.sh

MODAL_PROXY_TOKEN_FILE=/tmp/modal_proxy_token.json \
MODAL_ENDPOINT_URL=https://arthurcolle--ep-agent-server.us-west.modal.direct \
scripts/test_modal_dsco_live.sh
